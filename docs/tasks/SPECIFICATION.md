# Техническое задание

## Разработка корпоративной модульной Web-платформы

Версия: 1.0

Статус: Initial Draft

Основой для UI и UX берем EPS (расположен в папке reference)

------------------------------------------------------------------------

# 1. Назначение системы

Разработать корпоративную модульную Web-платформу для эксплуатации во
внутреннем контуре предприятия без доступа к сети Интернет.

Платформа должна обеспечивать единое пространство для работы нескольких
информационных систем (модулей), имеющих общую авторизацию, единое
управление безопасностью, аудитом, телеметрией и настройками.

Система должна проектироваться таким образом, чтобы можно было
независимо разрабатывать, обновлять, отключать и подключать отдельные
модули без нарушения работы остальных компонентов.

# 2. Технологический стек

-   Frontend: Next.js, React, TypeScript
-   Backend: Next.js API Routes / Route Handlers, REST API, TypeScript
-   Reverse Proxy: nginx
-   База данных: PostgreSQL
-   ОС: Ubuntu Server 24.04 LTS
-   Развертывание: локальная виртуальная машина без доступа во внешнюю
    сеть.

# 3. Архитектура

Browser → HTTPS → nginx → Shell → Modules (EPS, MRO, SRM, WMS) →
PostgreSQL.

Shell является центральной точкой входа и отвечает за авторизацию, RBAC,
маршрутизацию, мониторинг, аудит, телеметрию и управление модулями.

# 4. Основные требования

-   Модульная архитектура (Plugin-first).
-   Взаимодействие модулей только через REST API.
-   Независимое развертывание и обновление модулей.
-   Graceful degradation при отказе любого модуля.
-   LDAP Bind Authentication с поддержкой Mock-режима.
-   Полноценная RBAC.
-   CRUD для всех сущностей.
-   Централизованный аудит.
-   Централизованное структурированное логирование (JSON).
-   Health Check всех модулей.
-   Телеметрия (CPU, RAM, Disk, Network, DB, Latency).
-   Защита по принципу Zero Trust.
-   Защита от OWASP Top 10.
-   Service Registry модулей.
-   Безопасное межмодульное взаимодействие с сервисными JWT.
-   Централизованное управление настройками.
-   OpenAPI 3.1 для всех REST API.
-   Unit, Integration, API, Security и RBAC тесты.

# 5. Модули

-   Shell
-   EPS (система паспортизации оборудования)
-   MRO (ТОИР)
-   SRM (система подачи и выполнения заявок)
-   WMS (система склада)

# 6. Требования безопасности

-   LDAP Bind Authentication.
-   Mock пользователи для разработки.
-   RBAC.
-   Secure Cookie, HttpOnly, SameSite.
-   Session Timeout.
-   Parameterized SQL.
-   Проверка прав для каждого API и межмодульного вызова.
-   Аудит всех операций.
-   Централизованное логирование.

# 7. Результат

Автономная корпоративная модульная платформа с единым Shell, безопасным
взаимодействием модулей, централизованным управлением, аудитом,
мониторингом и возможностью расширения без изменения архитектурного
ядра.
